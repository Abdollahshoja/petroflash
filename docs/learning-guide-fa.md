مسیر محلی واقعی پروژه:


نام پوشهٔ والد با وجود املای فعلی اشکالی در Git ایجاد نمی‌کند. مخزن واقعی پوشهٔ petroflash است.

### دستورهای اجراشده

```powershell
git clone https://github.com/Abdollahshoja/petroflash.git
cd petroflash
git remote -v
git status
git log -1 --format=fuller
git config user.name
git config user.email
```

| دستور | معنی و دلیل |
|---|---|
| clone | دریافت فایل‌ها و تاریخچهٔ مخزن و ایجاد اتصال origin |
| cd | ورود به پوشهٔ مخزن برای اجرای فرمان‌ها |
| remote -v | نمایش نشانی دریافت و ارسال |
| status | بررسی شاخه، تغییرات و هماهنگی با مرجع دوردست محلی |
| log | مشاهدهٔ commit و اطلاعات نویسنده و ثبت‌کننده |
| config user.name/email | مشاهدهٔ هویت مورد استفاده در commitهای بعدی |

نام نویسندهٔ محلی تنظیم شده بود و ایمیل نیز موجود بود؛ نیازی به تنظیم دوباره نداشت. هویت commit با مجوز ورود و ارسال به GitHub یکی نیست. توانایی clone نیز به‌تنهایی حق push را ثابت نمی‌کند؛ push بعدی آن را تأیید کرد.

اولین commit مخزن با شناسهٔ کوتاه 1a23197 در ۸ اکتبر ۲۰۲۶ ساعت ۱۷:۲۱:۲۵ با اختلاف زمانی +03:30 ثبت شده است. زمان commit سابقهٔ ثبت نسخه است؛ مدت واقعی کار یا اثبات مستقل زمان ایجاد ایده نیست.

محیط مجازی به‌تنهایی بازتولیدپذیری کامل ایجاد نمی‌کند. پس از نصب وابستگی‌ها باید نسخه‌های آن‌ها و روش نصب ثبت شود. فایل محیط مجازی قابل‌حمل بین دستگاه‌ها نیست؛ در دستگاه جدید آن را دوباره می‌سازیم.

## ۸. فایل .gitignore و فایل‌های تولیدشده

قواعد زیر برای حذف محیط و خروجی‌های موقت از پیگیری Git اضافه شدند:

```gitignore
.venv/
__pycache__/
*.py[cod]
.ipynb_checkpoints/
.pytest_cache/
.env
```

| الگو | دلیل |
|---|---|
| .venv/ | وابستگی‌های نصب‌شده و فایل‌های وابسته به دستگاه |
| __pycache__/ و *.py[cod] | بایت‌کد تولیدشده از کد منبع |
| .ipynb_checkpoints/ | نسخه‌های موقت Jupyter |
| .pytest_cache/ | خروجی موقت ابزار آزمون احتمالی آینده |
| .env | تنظیمات محلی که ممکن است اطلاعات محرمانه داشته باشند |

قرارگرفتن یک فایل در ignore آن را از دیسک حذف نمی‌کند. اگر قبلاً تحت پیگیری Git بوده باشد، افزودن الگو به‌تنهایی پیگیری آن را متوقف نمی‌کند.

دستور تشخیصی ارائه‌شده:

```powershell
git check-ignore .venv/pyvenv.cfg
```

هشدار LF/CRLF هنگام add به تفاوت پایان خط در سیستم‌ها مربوط بود. commit و push با موفقیت انجام شد؛ پس این پیام در آن اجرا خطای متوقف‌کننده نبود. سیاست یکنواخت پایان خط در صورت نیاز با .gitattributes جداگانه تعریف می‌شود.

## ۱۲. آموزش شی‌گرایی با PropertyRecord

### مسئله

ذخیرهٔ یک عدد بدون واحد و منبع برای پژوهش کافی نیست. PropertyRecord قرارداد مشترک نگهداری هر خاصیت است. Component در مرحلهٔ بعد، این رکوردها را به یک ماده و معنای فیزیکی مشخص متصل خواهد کرد.

| فیلد | معنی |
|---|---|
| value | مقدار عددی متناهی |
| unit | واحد صریح، مانند K یا Pa؛ برای بی‌بعد 1 |
| source | نام منبع |
| reference | نشانی یا مشخصات استناد |
| method | روش تعیین یا مجموعه‌داده |
| data_kind | تجربی، ارزیابی‌شده یا تخمینی |
| uncertainty | عدم‌قطعیت مطلق با همان واحد، یا None |
| notes | توضیحات و تعریف عدم‌قطعیت |

None یعنی مقدار گزارش نشده؛ با صفر فرق دارد. فیلد notes برای عدم‌قطعیت لازم شده تا معلوم باشد مقدار، انحراف معیار، عدم‌قطعیت گسترش‌یافته یا تعریف دیگری دارد.

### اجزای زبان پایتون

| سازه | نقش در این کد |
|---|---|
| class | تعریف یک نوع داده و رفتار مرتبط |
| dataclass | ساخت خودکار سازنده و نمایش و مقایسهٔ داده |
| frozen=True | جلوگیری از تغییر معمول ویژگی‌ها پس از ساخت |
| slots=True | محدودکردن ویژگی‌های نمونه به فیلدهای تعریف‌شده |
| Enum | محدودکردن طبقه‌بندی داده به گزینه‌های مشخص |
| __post_init__ | کنترل مقادیر بلافاصله پس از ساخت نمونه |
| staticmethod | تابع کنترل که به وضعیت یک نمونه وابسته نیست |
| float \| None | مقدار می‌تواند عدد یا ناموجود باشد |
| TypeError | نوع ورودی نامناسب است |
| ValueError | مقدار ورودی با قرارداد سازگار نیست |

اعلان نوع یا type hint به‌تنهایی اعتبارسنجی زمان اجرا نیست؛ به همین دلیل کنترل صریح نوشته شده است. frozen یک مانع در برابر تغییر معمول ناخواسته است، نه سازوکار امنیتی مطلق.

bool در پایتون زیرنوع int است، ولی True نباید مقدار یک خاصیت فیزیکی پذیرفته شود؛ بنابراین جداگانه رد می‌شود. NaN و بی‌نهایت نیز با isfinite رد می‌شوند.

همهٔ خواص مثبت نیستند؛ برای مثال، ضریب بی‌مرکزی می‌تواند منفی باشد. پس رکورد عمومی مقدار منفی را مجاز می‌داند. Component باید دمای بحرانی مثبت و واحد صحیح هر فیلد را کنترل کند. کلاس فعلی تبدیل واحد یا اعتبار علمی منبع را انجام نمی‌دهد؛ فقط ساختار اولیهٔ رکورد را کنترل می‌کند.

درس طراحی: هر کلاس فقط قواعدی را اجرا کند که معنای آن‌ها را می‌داند. قواعد دمای بحرانی در سطح جزء قرار می‌گیرند، نه در ظرف عمومی همهٔ خواص.

## ۱۳. بررسی نحو: چه چیزی تأیید شد؟

```powershell

git status --short
```

فرمان نخست بدون خطا پایان یافت و دستور دوم ?? src/ نشان داد. ?? یعنی فایل جدید هنوز تحت پیگیری نیست، نه اینکه کد خطا دارد.

py_compile نحو فایل را بررسی و بایت‌کد تولید می‌کند؛ آزمون رفتار __post_init__ یا صحت داده‌های ترمودینامیکی نیست. در این نقطه فقط ایجاد فایل و پذیرش نحو تأیید شده است.

## ۱۴. آزمون‌های ارائه‌شده و وضعیت آن‌ها

کد tests/test_properties.py با ۱۱ روش آزمون ارائه شده است؛ اجرای آن هنوز تأیید نشده است.

آزمون‌ها شامل حفظ مقدار و منبع، تغییرناپذیری، رد NaN و بی‌نهایت، رد نوع نامناسب و bool، الزام واحد و منبع، الزام DataKind، پذیرش مقدار منفی عمومی، پذیرش عدم‌قطعیت مستند و رد عدم‌قطعیت نامعتبر یا بدون توضیح، و رد notes غیرمتنی هستند.

از unittest همراه پایتون استفاده شده تا برای شروع وابستگی اضافی نصب نشود. داده‌های ساختگی، قرارداد نرم‌افزاری را می‌آزمایند و نباید وارد بانک مواد شوند. subTest چند ورودی را در یک روش آزمون بررسی می‌کند؛ بنابراین تعداد حالت‌های بررسی‌شده از ۱۱ بیشتر است.

فرمان ارائه‌شده:

```powershell
.\.venv\Scripts\python.exe -c "import sys, unittest; sys.path.insert(0, 'src'); suite = unittest.defaultTestLoader.discover('tests'); result = unittest.TextTestRunner(verbosity=2).run(suite); sys.exit(0 if result.wasSuccessful() else 1)"
```

sys.path فقط در همان فرایند برای یافتن بستهٔ نصب‌نشده اصلاح می‌شود. discover فایل‌های آزمون را پیدا می‌کند. exit code صفر نشان‌دهندهٔ موفقیت و ۱ نشان‌دهندهٔ شکست است.

نتیجهٔ مورد انتظار: Ran 11 tests و OK. این نتیجه هنوز مشاهده نشده است. حتی در صورت موفقیت، فقط قراردادهای آزموده‌شده تأیید می‌شوند؛ ادعای کامل‌بودن آزمون‌ها یا اعتبارسنجی فیزیکی نداریم.

دستورهای زیر پیشنهاد شده بودند. خروجی جدید، commit و push را تأیید می‌کند، اما خروجی اجرای آزمون‌ها هنوز دریافت نشده است:

```powershell

git commit -m "feat: add immutable property records with provenance and tests"
git push -u origin stage-1-component-database
```

## ۱۹. تأیید آزمون‌ها و ورود به مدل جزء
