
نام نویسندهٔ محلی تنظیم شده بود و ایمیل نیز موجود بود؛ نیازی به تنظیم دوباره نداشت. هویت commit با مجوز ورود و ارسال به GitHub یکی نیست. توانایی clone نیز به‌تنهایی حق push را ثابت نمی‌کند؛ push بعدی آن را تأیید کرد.

## ۸. فایل .gitignore و فایل‌های تولیدشده

قواعد زیر برای حذف محیط و خروجی‌های موقت از پیگیری Git اضافه شدند:

```gitignore
.venv/
__pycache__/
*.py[cod]
.ipynb_checkpoints/
.pytest_cache/
.env
```

| الگو | دلیل |
|---|---|
| .venv/ | وابستگی‌های نصب‌شده و فایل‌های وابسته به دستگاه |
| __pycache__/ و *.py[cod] | بایت‌کد تولیدشده از کد منبع |
| .ipynb_checkpoints/ | نسخه‌های موقت Jupyter |
| .pytest_cache/ | خروجی موقت ابزار آزمون احتمالی آینده |
| .env | تنظیمات محلی که ممکن است اطلاعات محرمانه داشته باشند |

قرارگرفتن یک فایل در ignore آن را از دیسک حذف نمی‌کند. اگر قبلاً تحت پیگیری Git بوده باشد، افزودن الگو به‌تنهایی پیگیری آن را متوقف نمی‌کند.

دستور تشخیصی ارائه‌شده:

```powershell
git check-ignore .venv/pyvenv.cfg
```

هشدار LF/CRLF هنگام add به تفاوت پایان خط در سیستم‌ها مربوط بود. commit و push با موفقیت انجام شد؛ پس این پیام در آن اجرا خطای متوقف‌کننده نبود. سیاست یکنواخت پایان خط در صورت نیاز با .gitattributes جداگانه تعریف می‌شود.

## ۱۲. آموزش شی‌گرایی با PropertyRecord

### مسئله

ذخیرهٔ یک عدد بدون واحد و منبع برای پژوهش کافی نیست. PropertyRecord قرارداد مشترک نگهداری هر خاصیت است. Component در مرحلهٔ بعد، این رکوردها را به یک ماده و معنای فیزیکی مشخص متصل خواهد کرد.

| فیلد | معنی |
|---|---|
| value | مقدار عددی متناهی |
| unit | واحد صریح، مانند K یا Pa؛ برای بی‌بعد 1 |
| source | نام منبع |
| reference | نشانی یا مشخصات استناد |
| method | روش تعیین یا مجموعه‌داده |
| data_kind | تجربی، ارزیابی‌شده یا تخمینی |
| uncertainty | عدم‌قطعیت مطلق با همان واحد، یا None |
| notes | توضیحات و تعریف عدم‌قطعیت |

None یعنی مقدار گزارش نشده؛ با صفر فرق دارد. فیلد notes برای عدم‌قطعیت لازم شده تا معلوم باشد مقدار، انحراف معیار، عدم‌قطعیت گسترش‌یافته یا تعریف دیگری دارد.

### اجزای زبان پایتون

| سازه | نقش در این کد |
|---|---|
| class | تعریف یک نوع داده و رفتار مرتبط |
| dataclass | ساخت خودکار سازنده و نمایش و مقایسهٔ داده |
| frozen=True | جلوگیری از تغییر معمول ویژگی‌ها پس از ساخت |
| slots=True | محدودکردن ویژگی‌های نمونه به فیلدهای تعریف‌شده |
| Enum | محدودکردن طبقه‌بندی داده به گزینه‌های مشخص |
| __post_init__ | کنترل مقادیر بلافاصله پس از ساخت نمونه |
| staticmethod | تابع کنترل که به وضعیت یک نمونه وابسته نیست |
| float \| None | مقدار می‌تواند عدد یا ناموجود باشد |
| TypeError | نوع ورودی نامناسب است |
| ValueError | مقدار ورودی با قرارداد سازگار نیست |

اعلان نوع یا type hint به‌تنهایی اعتبارسنجی زمان اجرا نیست؛ به همین دلیل کنترل صریح نوشته شده است. frozen یک مانع در برابر تغییر معمول ناخواسته است، نه سازوکار امنیتی مطلق.

bool در پایتون زیرنوع int است، ولی True نباید مقدار یک خاصیت فیزیکی پذیرفته شود؛ بنابراین جداگانه رد می‌شود. NaN و بی‌نهایت نیز با isfinite رد می‌شوند.

همهٔ خواص مثبت نیستند؛ برای مثال، ضریب بی‌مرکزی می‌تواند منفی باشد. پس رکورد عمومی مقدار منفی را مجاز می‌داند. Component باید دمای بحرانی مثبت و واحد صحیح هر فیلد را کنترل کند. کلاس فعلی تبدیل واحد یا اعتبار علمی منبع را انجام نمی‌دهد؛ فقط ساختار اولیهٔ رکورد را کنترل می‌کند.

درس طراحی: هر کلاس فقط قواعدی را اجرا کند که معنای آن‌ها را می‌داند. قواعد دمای بحرانی در سطح جزء قرار می‌گیرند، نه در ظرف عمومی همهٔ خواص.

## ۵۱. مجموعهٔ آزمون منتخب از پیوست B

منبع کاربر: AppendixB-Whitson PVT SPE Phase Behavior monograph.pdf. شمارهٔ صفحات این فایل استخراجی از ۱ شروع می‌شود؛ برای ارجاع دقیق از شمارهٔ مسئله، جدول و معادله استفاده می‌کنیم.

مثال ۱۸ از متان/نرمال‌بوتان/نرمال‌دکان با z=(0.50,0.42,0.08) استفاده می‌کند. دکان در بانک فعلی نیست. برای بازتولید مثال از خواص جدول B-28 در دادهٔ مستقل آزمون استفاده می‌کنیم؛ افزودن دکان به بانک عملیاتی نیازمند ثبت منبع است. برای دکان طبق صورت مسئله باید رابطهٔ اصلاح‌شدهٔ m در معادلهٔ 4.22 به‌کار رود. kij و سایر قراردادها باید پیش از نهایی‌شدن آزمون از متن کنترل شوند؛ مقدار ناموجود بی‌اطلاع صفر فرض نمی‌شود.

در یک خط مثال، تبدیل دما با عدد 640 چاپ شده، اما محاسبات مجاور از 460 استفاده می‌کنند. تبدیل دقیق فارنهایت به رانکین از 459.67 استفاده می‌کند؛ بنابراین هم خطای چاپی و هم تقریب‌های تاریخی باید در بازتولید بررسی شوند. اعداد جدول نیز گرد شده‌اند. تلرانس مقایسه با کتاب باید با دقت اعداد چاپ‌شده متناسب باشد، نه صرفاً تلرانس حل‌گر.

## ۵۲. شروع حل راچفورد–رایس مستقل از EOS

معادله: f(beta)=sum[z_i*(K_i-1)/(1+beta*(K_i-1))]. در این مرحله z و K دادهٔ ورودی‌اند. فقط ریشهٔ داخل بازهٔ [0,1] محاسبه می‌شود. علامت دو سر بازه بررسی می‌شود؛ اگر ریشه محصور نباشد، خطا با توضیح وابستگی به K داده‌شده گزارش می‌شود و وضعیت تک‌فازی ترمودینامیکی اعلام نمی‌شود.

روش اولیه نصف‌کردن بازه است: ساده، محصور و قابل کنترل. معیار توقف، اندازهٔ باقی‌ماندهٔ معادله است؛ تمام‌شدن تعداد تکرار مجاز به معنی موفقیت نیست. در حالت تمام Kهای اجزای حاضر برابر یک، کسر بخار از این معادله قابل تعیین نیست و خطای حالت تباهیده لازم است. اجزای با z صفر در ارزیابی معادله کنار گذاشته می‌شوند.

این روش مرجع برای بررسی درستی است؛ ادعای بیشترین سرعت ندارد. بعداً نیوتن محصور را با همین آزمون‌ها مقایسه می‌کنیم. کد و آزمون‌های این گام در گفتگو ارائه می‌شوند؛ اجرای آن‌ها روی لپ‌تاپ هنوز تأیید نشده است. آخرین مجموعهٔ آزمون تأییدشده همچنان ۴۳ مورد است. کد TPConditions و چهار آزمون آن قبلاً پیشنهاد شده‌اند، ولی خروجی اجرای آن‌ها دریافت نشده است؛ بنابراین شمار آزمون بعدی بسته به وجود آن فایل‌ها متفاوت خواهد بود.

به‌روزرسانی وضعیت ثبت: CLI در e6bb5e9 و راهنمای ۰٫۲۷ در a778497 ثبت و ارسال شدند؛ خروجی git log و status همگام‌بودن شاخهٔ stage-2-mixture و پاک‌بودن پوشهٔ کاری را تأیید کرد. این اطلاعات، وضعیت قدیمی‌تر بخش‌های تاریخی را تکمیل می‌کند.

### نتیجهٔ اجرای محلی این گام

شش آزمون مستقل ماژول راچفورد–رایس در محیط دستیار اجرا شدند. در بررسی اولیه، ناسازگاری دادهٔ چاپی مسئلهٔ ۱۵ آشکار شد: z=(0.20,0.32,0.48) و K=(9.208,1.439,0.358) به beta=0.48291021815 می‌رسند، نه 0.48242 جدول B-20. علت اختلاف هنوز تعیین نشده است. آزمون این داده صرفاً باقی‌ماندهٔ معادله را کنترل می‌کند و بازتولید جواب کتاب محسوب نمی‌شود. برای بررسی مستقل حل‌گر، مسئلهٔ تحلیلی z=(0.5,0.5)، K=(2,0.5) با جواب دقیق beta=0.5 و موازنهٔ فازها نیز آزموده می‌شود. آزمون‌های مرزی با تلرانس عددی انجام می‌شوند.

فایل‌های تحویل: rachford_rice.py برای src/petroflash و test_rachford_rice.py برای tests. این اجرا فقط آزمون مستقل ماژول جدید است؛ آزمون یکپارچه روی مخزن کاربر هنوز باید اجرا شود. روش نصف‌کردن برای ساخت مرجع انتخاب شده و بعداً با نیوتن محصور ارتقا می‌یابد.
